# Render handoff

## Goal

The renderer should execute the approved visual strategy without re-deciding editorial hierarchy.

## Required fields

### Strategy
- opportunity ID;
- design job;
- objective;
- audience job;
- success signal.

### Output
- surface;
- aspect intent;
- slide count;
- export route;
- render tool.

### Assets
For each:
- source ID/path;
- role;
- rights;
- crop;
- required/optional;
- credit.

### Copy
- exact display text;
- placeholders clearly marked;
- source of truth;
- line-break intent only when necessary.

### Data
- exact values;
- labels;
- source;
- visual representation.

### Visual system
- concept;
- composition;
- hierarchy;
- type roles;
- color roles;
- photo treatment;
- logo;
- sponsor.

### Slides
For each:
- function;
- primary message;
- visual;
- text;
- data;
- layout logic;
- transition/continuity note.

### Accessibility
- contrast;
- alt text;
- reading order;
- no-color-only meanings.

### Export
- current dimensions;
- format;
- compression;
- naming;
- crop preview;
- platform/API requirements.

## Renderer freedom

Renderer may adjust:
- exact spacing;
- optical alignment;
- crop micro-adjustment;
- line breaks;
- type size within hierarchy;
- image correction;
- decorative micro-detail.

Renderer may not silently change:
- facts;
- score;
- quote;
- source data;
- headline meaning;
- visual job;
- sponsor obligation;
- rights;
- primary hierarchy.

## Replan triggers

Return to this skill if:
- actual image crop invalidates hierarchy;
- headline is materially longer;
- an asset becomes unavailable;
- rights change;
- sponsor requirement changes;
- data changes;
- platform crop/export changes make the design fail.
