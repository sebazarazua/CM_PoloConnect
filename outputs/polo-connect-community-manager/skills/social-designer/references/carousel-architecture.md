# Carousel architecture

## Why use a carousel

Use sequence when it adds:
- explanation;
- comparison;
- progression;
- storytelling;
- save value;
- multiple related facts;
- visual reveal.

Do not use multiple slides simply because the format allows them.

## Slide roles

Potential roles:

- `hook`
- `context`
- `evidence`
- `comparison`
- `detail`
- `quote`
- `timeline`
- `result`
- `consequence`
- `cta`

## Slide 1

Must work as a standalone feed object.

It should:
- communicate the topic;
- create a legitimate reason to swipe;
- avoid giving so little information that it becomes clickbait.

## Progression

Each slide should change the viewer's understanding.

Bad:
1. headline
2. same headline + photo
3. same idea + stat
4. CTA

Good:
1. result/claim
2. how it happened
3. key player/horse/stat
4. what it changes next

## Continuity

Maintain continuity through:
- grid logic;
- type roles;
- color family;
- metadata;
- image treatment;
- pacing.

Do not clone every slide.

## Length

Use the minimum number of slides needed.

Stop when the story is complete.

## Swipe transitions

Visual continuation across slides is optional.

Do not use connected panoramas when they harm independent readability or platform crop behavior.

## Final slide

Useful functions:
- consequence;
- schedule;
- next match;
- source/credits;
- CTA;
- summary.

Avoid generic "follow us" endings unless strategically justified.
