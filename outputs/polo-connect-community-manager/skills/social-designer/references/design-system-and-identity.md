# Design system and identity

## Goal

Build recognition through a coherent system while allowing strong editorial variation.

## Identity layers

### Fixed / slow-moving
Examples:
- logo;
- core color tokens;
- core typography;
- spacing logic;
- icon style;
- data/score package;
- photography principles.

These should change infrequently.

### Flexible
Examples:
- composition;
- photo crop;
- background treatment;
- scale;
- type size;
- information density;
- accent behavior;
- motion derivative.

These should respond to content.

### Contextual
Examples:
- tournament color;
- team color;
- sponsor integration;
- urgency state;
- celebratory treatment;
- archive treatment.

Contextual decisions must not erase Polo Connect identity.

## Recognition sources

Prefer recognition through:
- consistent editorial judgment;
- typography roles;
- score/data language;
- subtle brand mark;
- recurring metadata treatment;
- photography quality;
- clear hierarchy.

Avoid relying solely on:
- large logo;
- same frame on every post;
- same background;
- same gradient;
- same headline position.

## Brand system maturity

If a formal Polo Connect design system does not yet exist, separate:
- temporary working conventions;
- decisions proposed for permanent adoption.

Do not silently promote one post's style into a permanent brand rule.

## Tokens

When available, reference named tokens rather than raw values.

Examples:
- `color.brand.primary`
- `color.surface.dark`
- `type.display`
- `type.body`
- `space.2`
- `radius.card`

Rendering tools may map tokens to platform-specific implementations.

## Premium positioning

Premium can come from:
- strong photography;
- restraint;
- typography;
- space;
- confidence;
- detail quality;
- fewer competing messages.

It does not require:
- gold;
- serif;
- black background;
- luxury clichés.
