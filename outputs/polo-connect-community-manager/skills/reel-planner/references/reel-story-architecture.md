# Reel story architecture

## Principle

A Reel is a compressed audience experience, not a sequence of pretty clips.

Choose one dominant narrative function.

## Common architectures

### Peak first
`peak action -> context -> replay/angle -> consequence`

Use when:
- decisive moment is visually clear;
- immediacy is the value;
- audience can understand enough from action.

### Result first
`result -> proof/moment -> reaction -> implication`

Use when:
- result is the audience's primary question;
- speed matters;
- footage supports the outcome.

### Tension build
`setup -> stakes -> progression -> payoff`

Use when:
- suspense survives delayed reveal;
- viewer needs context before the moment.

Do not use for obvious breaking results if delay feels manipulative.

### Character
`person -> action -> detail -> reaction/consequence`

Use for:
- player;
- horse;
- groom/team;
- coach;
- spectator;
- behind-the-scenes subject.

### Explainer
`claim/question -> visual evidence -> simplified context -> takeaway`

Use for:
- rules;
- handicap;
- tournament structure;
- statistics.

### Atmosphere
`arrival/detail -> scale -> action -> human beat`

Use for:
- venue;
- final day;
- premium event;
- behind-the-scenes.

### Quote-led
`strong quote -> visual evidence/context -> consequence`

Use only when quote is genuinely strong.

## Story compression

Remove:
- duplicated angles;
- establishing shots with no job;
- excessive intros;
- generic celebrations when a specific reaction exists;
- slow-motion that adds no information or emotion;
- context the caption can carry instead.

## Ending

Good endings may:
- reveal consequence;
- land reaction;
- show score;
- transition to next event;
- deliver CTA;
- let natural sound resolve.

Avoid generic logo outro unless required.
