# Templates and variation

## Purpose

Templates accelerate recurring work while protecting consistency.

## Template families

Potential reusable systems:
- final result;
- fixture;
- live now;
- ranking;
- player stat;
- horse feature;
- quote;
- news/breaking;
- tournament explainer;
- carousel editorial;
- replay available;
- sponsor module.

These are not mandatory.

## Template states

### `stable`
Repeatedly useful and brand-approved.

### `experimental`
Being tested.

### `deprecated`
No longer recommended.

## Template structure

Separate:
- fixed tokens;
- editable slots;
- optional modules;
- content constraints;
- allowed variation.

## Variation

A template should allow variation through:
- photography;
- crop;
- headline length;
- data module;
- accent;
- slide sequence;
- secondary information.

Avoid output that looks batch-generated.

## New template creation

Create a reusable system when:
- the content type recurs;
- the production cost is meaningful;
- the audience recognizes the pattern;
- consistency improves utility;
- variation can remain healthy.

Do not create a permanent template from every one-off post.

## Fatigue

Monitor:
- same composition;
- same background;
- same oversized number;
- same headline treatment;
- same frame;
- same CTA card.

A template can be functionally correct but visually exhausted.
